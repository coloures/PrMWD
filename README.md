# Лабораторная работа №4: Нейронные сети и современные подходы

## Цель
Освоить нейросетевые подходы к табличным данным, методы представления текста (TF-IDF, эмбеддинги,
трансформеры) и методы снижения размерности для визуализации и анализа.

## Вариант и данные
- **Вариант №1** — **IMDB Movie Reviews (50k)** (классический `aclImdb`), задача —
  **бинарная классификация тональности** (2 класса: positive / negative). Особенности варианта:
  длинные тексты, сбалансированные классы.
- Ноутбук: `src/notebooks/laboratory_4.ipynb` (выполнен: все таблицы, графики и выводы внутри).
- Данные: `src/data/raw/imdb_reviews.csv` — 50 000 отзывов (25 000 train / 25 000 test,
  по 12 500 positive и 12 500 negative в каждой части), **под DVC**. Средняя длина отзыва ≈ 231 слово
  (медиана 174, максимум 2470).
- Предобученные модели скачиваются один раз и кэшируются на уровне пользователя (в Git/DVC не хранятся):
  **`word2vec-google-news-300`** (~1.7 ГБ) — через `gensim.downloader` в `~/gensim-data`;
  `all-MiniLM-L6-v2` (~90 МБ) — через `sentence-transformers` в `~/.cache/huggingface`;
  архив IMDB (84 МБ) — из первоисточника (Stanford).

## Что реализовано (по шагам задания)

| Шаг | Реализация |
|---|---|
| Загрузка данных | Скачивание `aclImdb_v1.tar.gz`, разбор 50k отзывов в `DataFrame(review, label, split)`, кэш в `src/data/raw/imdb_reviews.csv` |
| Предобработка текста | Нижний регистр, удаление HTML `<br />`, пунктуации/цифр, слов короче 2 букв и стоп-слов (`ENGLISH_STOP_WORDS`); 231 → 106 токенов. Для трансформеров оставлен **сырой** текст |
| Baseline TF-IDF | `TfidfVectorizer` (уни- **и** биграммы, `max_features=10000`, `min_df=2`, `sublinear_tf`) + `LogisticRegression` (`liblinear`) внутри `Pipeline` |
| Статические эмбеддинги | **`word2vec-google-news-300` через `gensim.downloader.load(...)`** (3 млн слов × 300d), вектор документа = **усреднение векторов известных слов** (покрытие токенов 96.3%) + `LogisticRegression` |
| Современные эмбеддинги | **Sentence-Transformers `all-MiniLM-L6-v2`** (384d, обрезка 256 токенов, `normalize_embeddings=True`) + `LogisticRegression` и `LGBMClassifier` |
| Сравнение | Сводная таблица метрик (Accuracy, F1, Precision, Recall, ROC-AUC) на тестовой части 25k |
| Снижение размерности | **PCA до 50 компонент** → **t-SNE** и **UMAP** (2D) для эмбеддингов Word2Vec (лучший эмбеддинг-метод) и MiniLM; scatter-plot с цветовой кодировкой классов + `silhouette_score` |
| Воспроизводимость | `SEED=42`, официальный train/test-сплит IMDB, кэш эмбеддингов, зависимости в `requirements.txt` |

## Результаты

### Сравнение методов (тестовая часть, 25 000 отзывов)
| Метод | Accuracy | F1 | Precision | Recall | ROC-AUC |
|---|---|---|---|---|---|
| **TF-IDF (uni+bi) + LogReg** | **0.8866** | **0.8872** | **0.8828** | **0.8916** | **0.9547** |
| **Word2Vec-300 (mean) + LogReg** | 0.8488 | 0.8487 | 0.8495 | 0.8478 | 0.9245 |
| MiniLM (SBERT) + LogReg | 0.8110 | 0.8103 | 0.8134 | 0.8072 | 0.8950 |
| MiniLM (SBERT) + LightGBM | 0.7926 | 0.7910 | 0.7974 | 0.7847 | 0.8792 |

**Главные результаты:**
1. Лучший — классический **TF-IDF + LogReg** (ROC-AUC 0.9547), но разрыв с эмбеддингами небольшой:
   **+0.0302** над лучшим эмбеддинг-методом. Тональность IMDB сильно выражается прямыми лексическими
   маркерами (`great`, `best`, `wonderful` ↔ `worst`, `awful`, `waste`, `boring`) — TF-IDF с биграммами
   ловит их идеально, а линейная модель обучена под конкретную задачу на 25k примеров.
2. **Статические `word2vec-google-news-300` (усреднение слов) обошли sentence-трансформер на +0.0296
   ROC-AUC** — главный неожиданный результат. Причины: MiniLM обрезает отзыв до 256 токенов (теряется
   хвост текста); `all-MiniLM-L6-v2` не дообучалась на длинных отзывах и оптимизирована под семантическое
   сходство, а не под тональность; у Google News-векторов 300 измерений и словарь 3 млн слов, поэтому
   даже простое усреднение даёт богатое представление.
3. **LogReg > LightGBM на MiniLM** (0.8950 против 0.8792): на плотных 384-мерных признаках
   L2-регуляризация устойчивее разбиения признаков в деревьях.

### Словарь и скорость
| Показатель | Значение |
|---|---|
| Уникальных слов в корпусе (после очистки) | 99 088 |
| Найдено векторов в `word2vec-google-news-300` | 58 394 |
| Покрытие токенов (train) словарём модели | 96.3% |
| Загрузка модели Word2Vec + отбор словаря корпуса | 25 c |
| Усреднение слов для 25k документов | 4 c |
| Обучение TF-IDF + LogReg (25k, 10k n-грамм) | ~10 c |
| Обучение LogReg / LightGBM на эмбеддингах MiniLM | ~0.1 c / ~10 c |
| **Кодирование 50k отзывов MiniLM (CPU, batch 64, 256 токенов)** | **594 c (train) + 710 c (test) ≈ 22 мин** |

### Снижение размерности и визуализация (PCA-50 → t-SNE / UMAP)
Подвыборка 5 000 отзывов (2500/2500), цепочка PCA(50) → t-SNE и UMAP:

| Метод | PCA-50 silhouette | t-SNE silhouette | UMAP silhouette | PCA-50 explained var |
|---|---|---|---|---|
| MiniLM (SBERT) | 0.016 | 0.021 | 0.029 | 54.5% |
| Word2Vec-300 (mean) | 0.028 | 0.060 | 0.043 | 66.1% |

Классы **не образуют компактных разделимых кластеров** (silhouette 0.016–0.060): тональность — не
отдельные «острова» в пространстве эмбеддингов, а относительно слабое направление среди множества
семантических (жанр, сюжет, актёры, длина отзыва). Но структура **Word2Vec-300 заметно лучше, чем у
MiniLM** (silhouette в 2–3 раза выше), и это согласуется с качеством классификации: t-SNE дал максимальный
silhouette (0.060), UMAP — более выраженные локальные сгустки (0.043). Явных выбросов мало.

## Выводы
1. **TF-IDF + LogReg — лучший и самый дешёвый baseline** для тональности IMDB (ROC-AUC 0.9547).
2. **Статические Word2Vec-300 (усреднение) сильнее sentence-трансформера без дообучения** (+0.0296 ROC-AUC):
   для длинных текстов обрезка 256 токенов и «семантическая» настройка MiniLM мешают тональности.
3. **Классический пайплайн (TF-IDF / усреднённый Word2Vec + LogReg) полностью оправдан** для этой задачи:
   качество достигается в разы дешевле, чем кодирование 50k текстов нейросетью.
4. **Линейная модель на эмбеддингах лучше бустинга** — 300–384 плотных признака уже «сжимают» информацию.
5. **Визуализация показала**, что тональность IMDB — тонкое непрерывное направление в семантическом
   пространстве, а не чётко отделённые кластеры; при этом более сильное представление даёт и более
   выраженную структуру (Word2Vec-300 > MiniLM и по silhouette, и по метрикам).

## Зависимости
Базовый стек (`numpy`, `pandas`, `scikit-learn`, `matplotlib`, `seaborn`, `joblib`) + добавленное для ЛР4:

> **Про версию Python.** Проект использует **Python 3.12**. Строго говоря, `gensim` нужен именно ради
> `gensim.downloader`, а у него нет wheel-файлов под Python 3.14 (доступны только cp39–cp313). Поэтому

## Как запустить
```bash
# 1) зависимости (нужен Python 3.12/3.13 — из-за gensim)
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 2) выполнить ноутбук — интерактивно или целиком headless
jupyter lab src/notebooks/laboratory_4.ipynb
python -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=7200 src/notebooks/laboratory_4.ipynb

# 3) данные под контролем DVC (imdb_reviews.csv), при необходимости:
dvc pull
```

**Первый запуск** скачивает архив IMDB (84 МБ), модель `word2vec-google-news-300` (~1.7 ГБ; при загрузке
в память нужно ~4.3 ГБ RAM) и веса MiniLM (~90 МБ), после чего кодирует 50k отзывов MiniLM (~22 мин на CPU).
**Повторные запуски** используют кэши (`src/data/interim`, `~/gensim-data`, `~/.cache/huggingface`) и
проходят за ~2–3 минуты.
