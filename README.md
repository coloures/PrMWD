# Лабораторная работа №4: Нейронные сети и современные подходы

## Цель
Освоить нейросетевые подходы к табличным данным, методы представления текста (TF-IDF, эмбеддинги,
трансформеры) и методы снижения размерности для визуализации и анализа.

## Вариант и данные
- **Вариант №1** — **IMDB Movie Reviews (50k)** (классический `aclImdb`), задача —
  **бинарная классификация тональности** (2 класса: positive / negative). Особенности варианта:
  длинные тексты, сбалансированные классы.
- Ноутбук: `src/notebooks/laboratory_4.ipynb` (выполнен: все таблицы, графики и выводы внутри).
- Данные: `src/data/raw/imdb_reviews.csv` — 50 000 отзывов (25 000 train / 25 000 test,
  по 12 500 positive и 12 500 negative в каждой части), **под DVC**. Средняя длина отзыва ≈ 231 слово
  (медиана 174, максимум 2470).
- Статические векторы: `src/data/raw/glove-wiki-gigaword-100.gz` (128 МБ) — **тот же датасет, что отдаёт
  `gensim.downloader.load('glove-wiki-gigaword-100')`**, тоже под DVC.
- Первоисточники скачиваются один раз и кэшируются: архив IMDB (84 МБ, Stanford), файл word-векторов
  (зеркало `gensim-data`), веса `all-MiniLM-L6-v2` (~90 МБ, HuggingFace Hub).

## Что реализовано (по шагам задания)

| Шаг | Реализация |
|---|---|
| Загрузка данных | Скачивание `aclImdb_v1.tar.gz`, разбор 50k отзывов в `DataFrame(review, label, split)`, кэш в `src/data/raw/imdb_reviews.csv` |
| Предобработка текста | Нижний регистр, удаление HTML `<br />`, пунктуации/цифр, слов короче 2 букв и стоп-слов (`ENGLISH_STOP_WORDS`); 231 → 106 токенов. Для трансформеров оставлен **сырой** текст |
| Baseline TF-IDF | `TfidfVectorizer` (уни- **и** биграммы, `max_features=10000`, `min_df=2`, `sublinear_tf`) + `LogisticRegression` (`liblinear`) внутри `Pipeline` |
| Статические эмбеддинги | Предобученные **GloVe-100d**, вектор документа = **усреднение векторов известных слов** (покрытие 99.2%) + `LogisticRegression` |
| Современные эмбеддинги | **Sentence-Transformers `all-MiniLM-L6-v2`** (384d, обрезка 256 токенов, `normalize_embeddings=True`) + `LogisticRegression` и `LGBMClassifier` |
| Сравнение | Сводная таблица метрик (Accuracy, F1, Precision, Recall, ROC-AUC) на тестовой части 25k |
| Снижение размерности | **PCA до 50 компонент** → **t-SNE** и **UMAP** (2D) для эмбеддингов MiniLM (лучший эмбеддинг-метод) и GloVe; scatter-plot с цветовой кодировкой классов + `silhouette_score` |
| Воспроизводимость | `SEED=42`, официальный train/test-сплит IMDB, кэш эмбеддингов, зависимости в `requirements.txt` |

## Результаты

### Сравнение методов (тестовая часть, 25 000 отзывов)
| Метод | Accuracy | F1 | Precision | Recall | ROC-AUC |
|---|---|---|---|---|---|
| **TF-IDF (uni+bi) + LogReg** | **0.8866** | **0.8872** | **0.8828** | **0.8916** | **0.9547** |
| MiniLM (SBERT) + LogReg | 0.8110 | 0.8103 | 0.8134 | 0.8072 | 0.8950 |
| MiniLM (SBERT) + LightGBM | 0.7926 | 0.7910 | 0.7974 | 0.7847 | 0.8792 |
| GloVe-100 (mean) + LogReg | 0.7988 | 0.7976 | 0.8022 | 0.7930 | 0.8750 |

**Главный результат:** на IMDB классический **TF-IDF + LogReg обыграл нейросетевые эмбеддинги**
(+0.0597 ROC-AUC над MiniLM). Объяснение: отзывы обрезаются до 256 токенов, `all-MiniLM-L6-v2`
не дообучалась на IMDB, а тональность здесь сильно выражается прямыми лексическими маркерами, которые
TF-IDF с биграммами ловит идеально. Самые «весомые» n-граммы: `great`, `excellent`, `best`, `perfect`,
`wonderful` ↔ `worst`, `bad`, `awful`, `waste`, `boring`.

Среди методов на эмбеддингах лучший — **Sentence-Transformers (MiniLM) + LogReg** (ROC-AUC 0.8950),
он и взят для визуализации; GloVe (усреднение) слабее всех (0.8750), т.к. усреднение теряет порядок слов
(«not good» ≈ «good»). Покрытие словаря GloVe — 99.2% (в корпусе 99 088 слов, нашлось 73 973 вектора),
поэтому дело не в нехватке словаря, а именно в усреднении. `LightGBM` на 384-мерных эмбеддингах
оказался **хуже** линейной модели (переобучается на «сжатых» признаках).

### Скорость
| Этап | Время |
|---|---|
| Обучение TF-IDF + LogReg (25k, 10k n-грамм) | ~12 c |
| Обучение LogReg на GloVe-векторах | ~0.2 c |
| Обучение LogReg / LightGBM на эмбеддингах MiniLM | ~0.1 c / ~9 c |
| **Кодирование 50k отзывов MiniLM (CPU, batch 64, 256 токенов)** | **594 c (train) + 710 c (test) ≈ 22 мин** |

### Снижение размерности и визуализация (PCA-50 → t-SNE / UMAP)
Подвыборка 5 000 отзывов (2500/2500), цепочка PCA(50) → t-SNE и UMAP:

| Метод | PCA-50 silhouette | t-SNE silhouette | UMAP silhouette | PCA-50 explained var |
|---|---|---|---|---|
| MiniLM (SBERT) | 0.015 | 0.021 | 0.029 | 54.5% |
| GloVe-100 (mean) | 0.022 | 0.035 | 0.029 | 88.1% |

Классы **не образуют компактных разделимых кластеров** (silhouette ≈ 0.015–0.035): тональность —
не отдельные «острова» в пространстве эмбеддингов, а относительно слабое направление среди множества
семантических (жанр, сюжет, актёры, длина отзыва). **UMAP** даёт чуть более выраженную локальную
структуру, чем t-SNE, но чистого разделения по классам не даёт ни один метод; явных выбросов мало.
PCA-50 объясняет 54.5% дисперсии у MiniLM (признаки размазаны по многим компонентам) и 88.1% у GloVe
(усреднённые векторы живут в низкоразмерном подпространстве).

## Выводы
1. **TF-IDF + LogReg — лучший и самый дешёвый baseline** для тональности IMDB (ROC-AUC 0.9547).
2. **Нейросетевые эмбеддинги без дообучения уступают** (+0.0597 к TF-IDF по ROC-AUC у MiniLM); выигрыш
   от них ожидаем при fine-tuning и на коротких текстах без явных лексических маркеров.
3. **Контекстные эмбеддинги > статические усреднённые** (MiniLM на +0.0199 ROC-AUC над GloVe).
4. **Линейная модель на эмбеддингах лучше бустинга** — 384 плотных признака уже «сжимают» информацию.
5. **Визуальная разделимость ≠ качество классификации:** у GloVe silhouette чуть выше, чем у MiniLM,
   хотя классификация хуже — линейный классификатор использует направление, не видное как кластеры.
6. **Визуализация показала**, что тональность IMDB — это тонкое непрерывное направление в семантическом
   пространстве, а не чётко отделённые кластеры; поэтому t-SNE/UMAP картинки выглядят «смешанными».

## Как запустить
```bash
# 1) зависимости
.venv\Scripts\activate
pip install -r requirements.txt

# 2) выполнить ноутбук — интерактивно или целиком headless
jupyter lab src/notebooks/laboratory_4.ipynb
python -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=7200 src/notebooks/laboratory_4.ipynb

# 3) данные под контролем DVC (imdb_reviews.csv + glove-wiki-gigaword-100.gz), при необходимости:
dvc pull
```

**Первый запуск** скачивает архив IMDB (84 МБ), word-векторы GloVe (128 МБ) и веса MiniLM (~90 МБ),
а затем кодирует 50k отзывов (~22 мин на CPU). **Повторные запуски** используют кэш
(`src/data/interim`) и проходят за ~2 минуты.
